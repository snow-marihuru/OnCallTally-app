# OnCallTally-app

電話当番表（担当者ごとの担当期間）から、指定した集計期間内の当番日数を「平日／土曜日／日祝日」区分別に人ごとへ自動集計し、区分別単価に基づく手当支給額とあわせてExcel（.xlsx）で出力するWebアプリです。給与計算のための当番日数カウント・手当額計算を手作業で行う手間とミスをなくすことを目的としています。

## 社内PCでの利用方法（推奨）

ターミナル操作なしで、ダブルクリックだけで使えるようにするための2つのファイルを用意しています。

1. **初回のみ**：[setup.bat](setup.bat) をダブルクリックします。Pythonのインストール確認、必要なパッケージのインストールを自動で行います。
   - 事前にPython 3.12系のインストールが必要です（[公式サイト](https://www.python.org/downloads/)からダウンロードし、インストール時に「Add python.exe to PATH」に必ずチェックを入れてください）。
   - 完了まで画面の指示に従ってください。エラーが出た場合は表示内容を確認してください（ウィンドウは自動では閉じません）。
2. **2回目以降**：[start_app.bat](start_app.bat) をダブルクリックします。アプリが起動し、数秒後にブラウザが自動で開きます。
   - 起動時に開くウィンドウ（黒い画面）は、アプリが動いている間ずっと開いたままにしてください。
   - 使い終わったら、そのウィンドウを閉じるとアプリが終了します。

このファイル一式（`app.py`や`setup.bat`を含むフォルダ全体）を、利用するPCにコピーしてから実行してください。

## 手動でセットアップ・起動する場合（開発者向け）

```bash
# セットアップ（初回のみ）
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements.txt

# 起動
.venv/Scripts/python.exe app.py
```

起動したら、ブラウザで以下のURLを開きます。

```
http://127.0.0.1:5000
```

終了するときは、コマンドを実行しているターミナルで `Ctrl + C` を押してください。

## 使い方

### 1. 担当者・当番期間の登録

画面上部のフォームに担当者名・開始日・終了日を入力して「登録」を押します。1件ずつ登録し、必要な人数・期間分繰り返します。日付は直接入力するか、カレンダーアイコンから選択できます。

登録済みの一覧は「編集」で内容を修正、「削除」で削除できます。「全件クリア」で一覧を空にできます。

### 2. 集計期間の指定・カレンダー確認

「集計開始日」「集計終了日」を指定します。給与締めが毎月15日のため、初期値は「前月16日〜当月15日」のサイクルになっています。

「カレンダーで確認」を押すと、その期間の当番カレンダーが表示されます。カレンダーは平日／土曜／日祝日を色分けして表示し、担当者が誰も登録されていない日は「未登録」と赤字で表示されます。

**区分の手動修正**：会社の公休日で本来は平日／土曜だが日祝日扱いにしたい日や、逆に祝日だが平日扱いにしたい日がある場合は、カレンダーの各日付マスのプルダウンから区分を選び直すと、その日の区分が上書きされます（赤い破線枠で「上書き済み」と分かるようになります）。自動判定の区分を選び直せば、上書きは解除されます。この修正はExcel出力にも反映されます。

### 3. Excelダウンロード

「Excelダウンロード」を押すと、担当者ごとの平日／土曜／日祝日／合計日数に加え、**手当支給額（円）**をまとめた一覧表（末尾に全体の合計行つき）が `.xlsx` ファイルとしてダウンロードされます。

手当支給額は、平日1日600円・土曜1日900円・日祝日1日1200円の単価で自動計算されます（単価を変更したい場合は `core.py` の `ALLOWANCE_RATES` を修正してください）。表の下には「手当内訳(検証用)」として、区分別の手当合計（平日手当合計・土曜手当合計・日祝日手当合計）と手当支給額合計を出力しており、上表の「合計」行の手当支給額と一致するかを目視で確認できます。

以下の場合はエラーが表示され、Excelは出力されません。登録内容を修正してから再度お試しください。

- 同じ日に複数の当番期間が重なっている（同一人物の重複登録も含む）
- 集計期間内に、誰も当番が登録されていない日がある

## 注意事項

- **入力データは保存されません。** 登録した当番期間や区分の手動修正は、アプリを再起動する（サーバーを終了して再度起動する）と失われます。集計結果は都度Excelファイルとして保存してください。
- 祝日判定には `jpholiday` ライブラリを使用しています。日本の祝日は法改正等で変わることがあるため、年1回程度 `requirements.txt` の `jpholiday` のバージョンを最新化し、`pip install -r requirements.txt` を再実行することをおすすめします。

## Renderへのデモ公開について

このアプリはRenderにデプロイできる状態になっています。ただし**本番運用ではなく一時的なデモ公開（研修アンケート提出用）を想定した最小限の対応**です。

### デプロイ手順の概要

1. GitHubリポジトリをRenderに接続し、「Web Service」として新規作成する。
2. Environment は Python を選択。ビルドコマンドは `pip install -r requirements.txt`。
3. 起動コマンドはリポジトリ直下の [Procfile](Procfile) の内容（`gunicorn app:app --bind 0.0.0.0:$PORT`）がそのまま使われる。Renderが自動でPORTを割り当て、`$PORT`として渡すので、アプリ側の設定変更は不要。
4. 必要に応じて環境変数 `SECRET_KEY` に適当なランダム文字列を設定する（下記「注意点」参照）。

### 注意点（デモ公開時）

- **Renderの無料プランはアイドル状態が続くとスリープし、次のアクセス時に再起動します。** このアプリはSECRET_KEYを未設定の場合、起動のたびにランダムな鍵を生成する設計のため、再起動が起きると、それまで入力していたデータ（セッションに保持している登録内容）が突然消えたように見えることがあります。デモの見た目上の挙動を安定させたい場合は、Renderの環境変数に `SECRET_KEY` を固定値で設定してください。
- 本アプリは元々データを保存しない設計（ブラウザのセッションのみに保持）です。この方針自体はRender上でも変わりません。複数人が同時にアクセスした場合、それぞれ別々の入力内容になります（データが共有されるわけではありません）。
- `debug`モードは環境変数 `FLASK_DEBUG` を明示的に `1`/`true` に設定しない限り無効です。Render側でこの環境変数は**設定しないでください**（本番相当の公開環境でデバッガを有効にすると、任意コード実行の重大なリスクがあります）。
- ログイン等のアクセス制限は実装していません。URLを知っていれば誰でも閲覧・操作できる状態になるため、公開URLの共有範囲には注意してください。
